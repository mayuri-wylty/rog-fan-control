# rog-fan-control

一键把华硕 ROG 笔记本风扇拉到比出厂/G-Helper「100%」更高的转速，关闭窗口即恢复。单文件、无需安装、无常驻进程。

> **仅在 ROG Zephyrus M16 GU603HM（i7-11800H + RTX 3060）上实测。** 其他机型的设备项和转速可能不同，请勿直接套用，见下方「兼容性」。

## 使用

1. 下载 `fan-control.cmd`。
2. 双击运行，弹出 UAC 点「是」（需要管理员权限访问 ASUS ACPI 驱动）。
3. 窗口里：

| 按键 | 档位 | 实测转速 |
|---|---|---|
| 默认 | 二档（CPU 偏高 / GPU 偏低） | CPU 约 7850 / GPU 约 7450 RPM |
| `1` | 一档（满速） | CPU 约 8300 / GPU 约 8400 RPM |
| `2` | 回到二档 | 同上 |

4. **关闭窗口或按 Ctrl+C，风扇范围自动写回原值。**

手动恢复（仅在异常中断后需要，如任务管理器强杀、断电）：直接双击 `fan-restore.cmd`（与 `fan-control.cmd` 放在同一文件夹），或命令行运行：

```bat
fan-control.cmd restore
```

## 原理

通过 `\\.\ATKACPI`（ASUS ACPI 驱动）发送 `DEVS` 调用，写风扇范围设备项：

- `0x00110022`：CPU 风扇范围
- `0x00110023`：GPU 风扇范围

出厂值为 CPU 200 / GPU 225（满值 255）。把它们提高即可抬高转速上限。实测写风扇曲线（`0x00110024/25`）和性能模式（`0x00120075`）会被固件接受（返回成功）但不生效，所以不走这两条路。

风扇范围项读回值不反映写入（始终是 200/225），转速要靠读风扇转速项 `0x00110013/14` 判断，因此工具每秒显示实时 RPM，并每 5 秒重写一次目标值。

## 安全与行为

- 写入前备份原值到 `%LOCALAPPDATA%\FanMax\range_backup.json`；恢复成功后删除该备份。
- 关闭窗口、注销、Ctrl+C 触发恢复。
- 不修改 BIOS/EC 固件，不安装驱动，不创建服务、计划任务或开机启动项。
- **写入的值可能在重启后仍然保留，不要指望重启恢复默认。** 实测遇到过窗口开着时关机，恢复来不及执行，二档值一直留在设备里，重启后转速仍偏高。
- **关机或重启前请先关闭工具窗口。**
- 若上次未正常退出，下次启动工具时会检测到残留备份，先自动恢复再继续，并提示「检测到上次未正常退出」。
- 若转速异常又不想再开工具，双击 `fan-restore.cmd` 手动写回出厂值（需与 `fan-control.cmd` 同一文件夹；改过文件名的话，改 `fan-restore.cmd` 里的名字即可）。
- 拉满只会让机器更凉，但风扇噪音和磨损会增加，请自行权衡。

## 与 G-Helper 共存

本工具只写风扇范围项，不改 G-Helper 的配置、曲线或性能模式。G-Helper 在切换性能模式、插拔电源时可能重新应用设置，若转速被盖掉，工具最多 5 秒后补回。**同时运行的受控测试没有做过**，如遇冲突请先退出 G-Helper。

## 兼容性

- 需要：Windows、管理员权限、ASUS 的 `ATKWMIACPIIO` 驱动（`\\.\ATKACPI` 可打开）。Armoury Crate 不需要运行。
- 已验证：ROG Zephyrus M16 GU603HM。
- 其他机型：设备项 ID 来自 G-Helper 源码，但不同机型的范围值、满值和转速不同，需自行验证。建议先只读探测（发送 `DSTS` 读取 `0x00110022/23` 和转速项），再决定是否写入。
